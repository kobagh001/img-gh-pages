# 画像投稿ギャラリー GitHub Pages サイト仕様書

このドキュメントは、AIエージェント（リポジトリ作成担当）に入力するための仕様書です。

---

## 1. 概要
- 個人用。エンタープライズ向けではない。
- このリポジトリは Private とする。

- **目的**: 限定メンバーで画像（イラスト・創作物）を投稿・共有できるギャラリーサイトを、GitHub Pages上に構築する。
- **公開範囲**: GitHub Pagesとして公開する静的サイト（閲覧は誰でも可能。投稿はリポジトリのコラボレーターのみ）。
- **投稿者**: リポジトリオーナー本人 + 限定メンバー（友人など）。GitHubの共同編集者（Collaborator）としてリポジトリに招待し、直接コミット（push）することで画像を追加する。
- **コンテンツの種類**: イラスト・創作物ギャラリー。

---

## 2. 技術スタック（推奨）

- **静的サイトジェネレーター**: [Eleventy (11ty)](https://www.11ty.dev/)
  - 理由: 軽量、テンプレートがシンプル、front matter形式のメタデータ管理と相性が良く、タグベースのフィルタリング機能も実装しやすい。
- **画像最適化**: [`@11ty/eleventy-img`](https://www.11ty.dev/docs/plugins/image/) プラグインを使用し、ビルド時に自動でリサイズ・圧縮・サムネイル生成を行う。
- **デプロイ**: GitHub Actions を使い、`main`ブランチへのpushをトリガーに Eleventy でビルド → GitHub Pages（`gh-pages`ブランチ or Pages用Actionsデプロイ）へ自動デプロイする。
- **フロントエンド**: 素のHTML/CSS/JavaScript（フレームワーク不要）。タグ絞り込み・モーダル表示はvanilla JSで実装する軽量な仕組みとする。

---

## 3. コンテンツ管理方法（投稿ワークフロー）

コラボレーターは以下の手順で画像を追加する：

1. `src/images/` ディレクトリに画像ファイルを追加する（例: `2026-09-22-作品タイトル.jpg`）。
2. 同名のメタデータファイル（YAML）を同じディレクトリに追加する（例: `2026-09-22-作品タイトル.yml`）。
   - 画像とメタデータをペアのファイルにすることで、複数人が同時に投稿してもコンフリクトしにくい構成にする。
3. `main`ブランチにpush（直接コミット）する。
4. GitHub Actionsが自動でビルド・画像最適化・デプロイを行い、サイトに反映される。

### ディレクトリ構成（案）

```
repo/
├── src/
│   ├── images/
│   │   ├── 2026-09-22-作品タイトル.jpg
│   │   └── 2026-09-22-作品タイトル.yml
│   ├── _includes/
│   │   └── layouts/base.njk
│   ├── index.njk          # ギャラリー一覧ページ
│   └── styles/
│       └── main.css
├── .eleventy.js
├── .github/
│   └── workflows/
│       └── deploy.yml     # ビルド＆デプロイ自動化
└── README.md               # 投稿方法の説明（コラボレーター向け）
```

### メタデータファイルの例（`2026-09-22-作品タイトル.yml`）

```yaml
title: "作品タイトル"
author: "投稿者名"
date: 2026-09-22
tags: ["イラスト", "オリジナル"]
description: "作品の説明文をここに書く。"
image: "2026-09-22-作品タイトル.jpg"
```

## 4. 機能要件

### 4.1 ギャラリー一覧（トップページ）
- 全投稿画像をグリッド形式（タイル状）で一覧表示する。
- 各サムネイルの下には **タイトルのみ** を表示する（投稿者・日付・説明文は表示しない）。
- タグ・カテゴリによる**絞り込み機能**を実装する（ページ遷移なしのクライアントサイドJSによるフィルタリングを想定）。
- 独立した「作品詳細ページ」（個別URL）は作らない。

### 4.2 詳細表示（モーダル）
- サムネイルをクリックすると、モーダルウィンドウがポップアップし、以下の情報を表示する：
  - 画像の拡大表示
  - タイトル
  - 投稿者名
  - 投稿日
  - タグ
  - 説明文
- モーダルは背景クリックまたは閉じるボタンで閉じられるようにする。

### 4.3 画像の自動最適化
- ビルド時に元画像を自動でリサイズ・圧縮する。
- 一覧表示用のサムネイル画像と、モーダル拡大表示用の画像（元画像よりは軽量化されたサイズ）の2種類を自動生成する。
- レスポンシブ画像（`srcset`）に対応する。

### 4.4 データモデル（画像ごとのメタデータ項目）
| 項目 | 必須 | 説明 |
|---|---|---|
| title | 必須 | 作品タイトル |
| author | 必須 | 投稿者名 |
| date | 必須 | 投稿日 |
| tags | 必須 | タグ（複数可、配列） |
| description | 必須 | 説明文 |
| image | 必須 | 画像ファイル名 |

---

## 5. 非機能要件

- **レスポンシブ対応**: PC・タブレット・スマートフォンいずれの画面幅でも見やすいレイアウトにする（CSS Grid / Flexboxベース）。
- **デザイン**: シンプル・モダンなライトテーマ。特別な指定はないため、AIエージェントのおすすめのデザインでよい（配色・フォント等は一任）。
- **パフォーマンス**: 画像最適化により、ページの読み込み速度を軽量に保つ。
- **メンテナンス性**: コラボレーターが画像ファイルとYAMLファイルのペアを追加するだけで投稿できる、シンプルな運用を維持する。

---

## 6. デプロイ・公開設定

- GitHub Actionsワークフロー（`.github/workflows/deploy.yml`）を用意し、`main`ブランチへのpush時に自動でビルド・デプロイする。
- GitHub Pagesの公開設定（Settings > Pages）で、Actionsからのデプロイを利用する設定にする。
